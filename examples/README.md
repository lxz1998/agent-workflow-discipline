# 第一次怎么跑通（10 分钟走查）

规则是抽象的，**这些文件长什么样**没人见过。这里放一套填好的最小样例，
演示四问在哪一步触发、卡点怎么写、交接怎么落笔。

场景（虚构）：**给一份月度销售表补一列"毛利率"**，中途发现数据口径不对。

---

## 第 0 步：先有这五个位置（可以就是五个 Markdown 文件）

| 文件 | 作用 | 样例 |
|---|---|---|
| `log/2026-03-11.md` | 发生了什么 | [看样例](log-2026-03-11.md) |
| `playbook.md` | 以后怎么做（口径、步骤） | [看样例](playbook.md) |
| `pitfalls.md` | 什么行不通 + 日期 + 失效条件 | [看样例](pitfalls.md) |
| `HANDOFF.md` | 现在停在哪 | [看样例](HANDOFF.md) |
| `TASKS.md` | 还剩什么（只能有一个"下一格"） | [看样例](TASKS.md) |

> 五个文件都在一个目录里就够了，不需要任何工具。
> 仓库里没有它们**是正常的**——它们在**你的项目**里，不在这个技能库里。

---

## 第 1 步：动手之前，四问

**目标**：给 `sales_2026-02.csv` 补毛利率列。

**① 先例**：查 `pitfalls.md` → 命中一条「这张表 1 月补过，`amount` 是含税，`cost` 是不含税，直接相除会虚高」（2026-02，失效条件：供应商改成含税报价时）。
**② 依据**：我能不能自己验证含税与否？→ 能，表里有 `tax_included` 列。**问题解决，不必问人。**
**③ 第二意见**：这个结论会被谁拿去决策吗？→ 会被用来定价，**要问**。但先做完 ④。
**④ 卡点**：暂时没卡。

**这里省掉了什么**：没问人"要不要含税"。第 ② 问就把它答了——**能自己验证的事不要问人**。

---

## 第 2 步：卡住了，怎么写

做到一半，发现 `cost` 有 12 行是空的。

```
卡在哪：cost 列 12/480 行为空，占比 2.5%
已排除：不是导出截断（行数对得上）、不是编码问题（其余列正常）
需要谁：采购同事确认这 12 个 SKU 是否还没录成本
```

**注意它没有说"我再试试"**——2.5% 的空值会让毛利率算错，这属于"结果不对"，不是"报错"。

---

## 第 3 步：交接怎么写

```markdown
停在：毛利率列已补 468 行，12 行待成本确认；未输出最终文件。

下次第一句：先确认 12 个 SKU 的成本，再跑最后一步导出。
⚠ 执行前先核对：pitfalls.md 里那条含税结论是否仍成立（若供应商已改含税报价，需重算成本）。
```

**最后那行是重点**：交接文件是"别人的记忆"，接手的人**先核对现状再执行**。
