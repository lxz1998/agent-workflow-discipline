# 动手前四问（Pre-Action Gate）

## 为什么要问

绝大多数返工不是"不会做"，是**在错误的前提下开始做**：
以为数据缺，其实库里有；以为没做过，其实手册早写了；以为改好了，其实改的是另一份。

四个问题各自对应一类失败，**按顺序问，第一个不过就别往下走**。

---

## 第一问：这件事有没有先例？

**查两样**：① 做过的事（日志 / 手册 / 弯路库）② 现在到底是什么状态（原文，不是记忆）。

**为什么两样都要**：只查先例会漏掉"情况变了"，只查现状会重复劳动。

**这一问最常抓到的错**：**凭记忆判断现状**。记忆里的版本可能已经被改过三轮，
而你以为它还是老样子，于是又立了一个已经做完的项。

> 判据：**说得出它现在长什么样吗？** 说不出来就先去看，别动手。

---

## 第二问：依据在不在手边？

**判据：这件事我能不能自己验证？**

- 能 → 直接做，不要问人
- 不能 → **先把"要什么才能验证"说清楚**，再决定是否求助

**这一问最常抓到的错**：**把自己列的清单当判据**。
"我以为需要 A、B、C"和"实际缺 A、B、C"是两件事——前者是猜测，后者要查。

> 判据：说"缺 X"之前，先证明"有 X 的样子是什么"，并查过一遍。

---

## 第三问：要不要第二意见？

**什么时候要**：
- 结论会被别人拿去决策（数字、口径、预算）
- 不可逆操作（删除、覆盖、对外发布）
- 有真实取舍（两条路都有人支持）

**什么时候不要**：纯查数、纯状态核实、纯执行已知步骤。
**每次都问第二意见，等于没有第二意见**——成本会高到没人愿意用。

**怎么问**（决定回答质量的一半）：
- 复核数字 → 给原始数据 + 口径，让它能自己复算
- 复核因果 → **主动交底你排除了哪些解释**，否则它只会重复你的逻辑
- 复核取舍 → 问"我这个取舍的前提成不成立"，别问"选哪个"

**收到意见之后**：**必须用原始数据复核再采纳**。顾问会算错，而且经常算错。

---

## 第四问：卡住了有没有说？

**这是最容易被跳过的一问，因为跳过它最舒服。**

三种典型表现：
1. **反复试同一个目标的不同方法**（第三种方法失败时就该停）
2. **自己给需求降级**（"时间紧，先不查了"）
3. **把推断写成结论**（"应该是……"直接变成"是……"）

**止损规则**：**同一个目标连续失败 3 次，立刻停**，输出三行：
现在卡在哪 / 已经排除什么 / 需要谁做什么。

**停之前先自问一句**：**这个目标还要不要？** 很多时候答案已经拿到了，继续做只是惯性。

---

## 四个问题的一张纸

```
□ 先例：查过日志/手册/弯路库？看过它现在的样子？
□ 依据：能自己验证吗？说"缺"之前查过吗？
□ 意见：会被拿去决策 / 不可逆 / 有取舍 → 问；纯执行 → 不问
□ 卡点：连续 3 次失败就停，说清"卡在哪 / 排除什么 / 需要谁"
```

## 适用边界

为 **有真实业务后果的操作**（改数据、对外交付、删除重建）设计。
探索性工作、写草稿、读文件不需要过这套——**过了反而是官僚**。
