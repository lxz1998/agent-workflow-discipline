# 阶段交接（Context Handoff）

## 什么时候用

- 一个阶段做完了，要开新会话继续
- 上下文快满了（换会话的代价是"重来一遍"，所以**先把状态写下来再换**）
- 有人要接手你手上的活

## 核心判断：这段东西该写到哪里

**大多数交接失败，不是写得少，是写错了地方。**

| 内容 | 写到哪 | 判据 |
|---|---|---|
| **发生了什么**（今天做了什么、结论是什么） | 工作日志（按日期） | 只对自己有用，**不需要别人照做** |
| **以后怎么做**（口径、步骤、规则） | 方法手册 | 下一个人会照着执行 |
| **什么行不通**（踩过的坑） | 弯路库 | 别人可能踩同一个 |
| **现在停在哪** | 交接文件 | 下一个会话第一句就能接上 |
| **还剩什么没做** | 任务板 | 有明确的下一格 |

**分流错了的后果**：把"今天踩的坑"写进日志 → 下一个人照旧踩；把"一次性的数据"写进手册 → 手册越来越厚，没人读。

## 三件事，缺一不算交接完

### ① 分流信息

按上表逐条判断，**一条信息只能进一个地方**。两处都写，必然一处滞后。

### ② 刷新存档位

至少三个：

| 存档位 | 写什么 |
|---|---|
| 交接文件 | 三段：**做成了什么 / 什么坏了 / 什么还不知道** |
| 任务板 | 勾掉做完的、新增冒出来的、**把"下一格"改成唯一一个** |
| 环境快照 | 只有机器真的变了才写；没变就写"无变化" |

**任务板只能有一个"下一格"。** 两个等于没有——下一个人会挑错的那个。

### ③ 写半成品位置

**这一条最容易漏，也最值钱。**

不要写"月报还在做"，要写：

> 停在：正文 01/03/05 三节已改，PDF 未重出。
> 下次第一句：先改 04b 的对外口径，再重出 PDF。

**判据**：下一个会话读到这句话，**不需要问任何问题就能接着干**。

## 三条常见错误

1. **只写"做完了什么"，不写"还差什么"** —— 下一个人会重做已经做完的。
2. **把结论写成过程**（"我查了 A、B、C"）—— 结论是"B 是对的"，过程没人要读。
3. **不留判断依据** —— 写"用 X 方案"，不写"为什么不用 Y"。下一个人会重新纠结一遍。

## 适用边界

为 **长期、多会话、多人（或人与 Agent 混合）协作** 的场景设计。
一次性任务、单人短会话不需要这套——**直接做完就行，交接反而增加负担。**
