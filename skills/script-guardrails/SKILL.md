# 数据脚本的四条铁律

## 为什么会写这份

统计过一批真实脚本（100 多个、两万行）：**99% 只用 print 不记日志、45% 有裸 `except: pass`、
只有 11% 支持 `--dry-run`**。

这些不是"风格问题"，它们共同导致一件事：**失败了但没人知道。**
数据静默缺块，报告照样出，月底对账才发现——那时候已经没人记得是哪次跑的。

---

## 铁律 1 · 失败必须能被看见

```python
# 禁止
except Exception:
    pass

# 最低要求
except Exception as e:
    print("失败：%s" % e, file=sys.stderr)
    return 1
```

**判据两条**：
- 跑完 `echo $?` 是 0，就代表全部成功
- **每次运行留一行回执**：`[done] 读入 N / 写入 M / 跳过 K / 耗时 Xs`

**为什么加第二条**：只打印到屏幕的脚本，出错后**无法追溯是哪一次入库造成的**，只能重跑。

---

## 铁律 2 · 事务必须；备份和 dry-run 只对"会删东西"的脚本

| 场景 | 事务 | `--dry-run` | 备份 |
|---|:-:|:-:|:-:|
| 只读取数 | — | 不需要 | — |
| 增量 upsert | **要** | 建议 | 不需要（重跑可恢复） |
| **区间重建 / 覆盖历史** | **要** | **必须** | **必须**（原行导 CSV） |

不要一刀切——每个脚本都补 dry-run 的成本，通常高于它挡住的损失。

---

## 铁律 3 · 金额用 Decimal，别用 float

```python
if abs(total - Decimal("93470.31")) > Decimal("0.01"):
    print("失败：金额合计不符，差 %s" % (total - Decimal("93470.31")), file=sys.stderr)
    return 2
```

**不要用 `assert` 做校验**：`python -O` 会剥掉它，校验会静默失效（Google Python Style Guide 明确禁止）。
临时脚本图快可以用，但要在脚本头注明"不会以 -O 运行"。

**金额求和必须用 Decimal**——float 比较会让这条校验本身误报或漏报。

---

## 铁律 4 · 跳过必须有上限

逐行处理允许跳过坏行，但要计数并在结尾判断比例：

```
跳过比例 > 1%（或 > 50 行）→ 退出码 2，并打印原因分布
```

**否则一个格式变化让九成行被跳过，脚本照样退出 0，报告少了九成数据没人发现。**

---

## 异常：两条规则，别分三类

> "环境类重试 / 数据类跳过 / 逻辑类抛"听起来对，但**写代码时没人能在 `except` 那一行判断它属于哪类**。

1. **默认不捕获**：让异常抛到 `main()` 外层，统一 `except Exception as e` → 记日志 → `return 1`
2. **只在两处允许捕获**：
   - **逐行循环里**：捕获 → 记行号与原因 → 计数 → 受"跳过上限"约束
   - **网络/数据库连接**：调**一个共用的重试函数**（固定 3 次、间隔递增），不要在脚本里各写各的

**重试只对明确的临时性错误**（超时、连接重置、429、5xx）。
**写入结果不明时先查状态再决定要不要重发**——盲目重试会重复写数据。

---

## 建表三条反模式

1. **用 `%` 拼 DDL**：列定义里出现 `%` 就炸 → 用 `",".join()` 或 `str.replace`
2. **以为 `CREATE TABLE IF NOT EXISTS` 能改结构**：不能，改列类型必须 DROP 再建
3. **保留字不加反引号**：`key` / `status` / `order` / `desc` 必须加

**行宽上限 65,535 字节是按「声明的长度之和」算的**；`TEXT` 在行宽里只记 9–12 字节
（不是 20——20 是指向溢出页的指针，两回事）。

## 附：`scripts/py_check.py`

把它放到你的 `tools/` 里，提交前跑一次：

```bash
python scripts/py_check.py <目录或文件>
```

会扫出：裸 `except: pass`、破坏性 SQL 缺 dry-run、金额求和未用 Decimal、
`load_workbook` 未加 `read_only`、有跳过逻辑但无上限、无运行回执。

**E 级必须改，W 级看情况。**

## 适用边界

为 **1–3 人、无 CI、脚本 100 个上下** 的团队设计。
有 CI 且有专职质量岗时，铁律 1 的第 2 条（回执）可以交给流水线；
测试覆盖很全时，铁律 3 的运行时校验可以省。
