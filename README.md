# agent-workflow-discipline

**给长期和 AI 协作的人用：三个动作，少走重复弯路。**

这套东西不是提示词技巧，是**流程约束**——回答三个问题：

| 技能 | 回答什么 | 用在哪 |
|---|---|---|
| [`pre-action-gate`](skills/pre-action-gate/SKILL.md) | **动手之前该问什么** | 每次要改数据、要对外交付、要新建东西 |
| [`second-opinion`](skills/second-opinion/SKILL.md) | **结论要不要找人复核、怎么问、怎么判** | 数字会被人拿去决策时 |
| [`context-handoff`](skills/context-handoff/SKILL.md) | **上下文要丢了，怎么把状态交出去** | 阶段结束、换会话、交接 |

三个是一套：**动手前拦住错前提 → 结论前拦住错自信 → 结束时拦住状态丢失。**

---

## 为什么值得装

它们不教你"怎么写更好的提示词"，它们对付的是三件反复发生、且每次都很贵的事：

1. **在错误的前提下开始做**——以为数据缺其实有、以为没做过其实做过了。
   代价通常是一整轮返工。
2. **把推断写成结论**——"应该是 X"直接变成"是 X"，然后被拿去决策。
   代价是别人照着错的数字做了决定。
3. **换会话时状态丢失**——上一个会话的结论、否定过的方案、停在哪一步，全没了。
   代价是从头再来一遍。

---

## 怎么装

每个技能是一个独立文件夹，`SKILL.md` 带 YAML frontmatter（`name` + `description`）。
支持 Agent Skills 的客户端（Claude Code、Codex、Gemini CLI 等）可以直接用：

```bash
# 放到你的技能目录
cp -r skills/* ~/.claude/skills/      # 或项目的 ./skills/
```

其他情况：把 `SKILL.md` 正文当作**系统提示的一部分**注入即可，不依赖任何运行时。

---

## 怎么用

**只在需要时加载**——三个技能的 `description` 都写成了"触发条件"，
Agent 匹配到场景才读，不会常驻占上下文。

人工使用：把三个 `SKILL.md` 当检查清单，一节一节过。
`pre-action-gate` 最后有一张四问的一页纸，可以直接贴在工位上。

---

## 适用边界（重要）

为 **1–3 人、无 CI、长期多会话、数据量中等** 的团队设计。

- **有 CI 和专职质量岗** → `pre-action-gate` 的第三问可以省（CI 会挡）
- **单机单人、任务都短** → `context-handoff` 基本不需要，直接做完就行
- **纯探索性工作** → 别过闸，过了反而官僚

**这套东西的价值在"少犯贵错"，不在"流程完整"。**
如果你的场景里犯错很便宜，那它对你就是多余的——这很正常，不用勉强套。

---

## 这些判据从哪来

不是从书上抄的，是**两个月里真实发生的返工换来的**，每一条都对应一次具体损失：

- "凭记忆判断现状 → 同一天重复立项 4 次"
- "参数名 `both` 其实是'全部'，不是'两个' → 复核成本翻三倍"
- "把'恰好巧合'当成'独立印证' → 差点带着假证据去汇报"
- "失败三次还在换第四种方法 → 该停的时候没停"

具体案例在 [`docs/why.md`](docs/why.md)（已脱敏，只留可迁移的部分）。
